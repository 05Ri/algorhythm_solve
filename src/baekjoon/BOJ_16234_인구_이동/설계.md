# ☑️ 문제
⛓️‍💥 [16234 인구 이동](https://www.acmicpc.net/problem/16234)

## ⌨️ 입력

- 땅의 크기 N(1 ~ 50), 기준인 L명 이상, R명 이하
    > nations[][] / L과 R은 1 ~ 100

<br/>

## 🖥️ 출력

- 인구 이동이 며칠 동안 발생하는지
    > int movingDays

<br/>

## 💭 문제 조건 정의 & 해결

- 두 나라의 인구 차이가 L ~ R이 아닌 칸은 인구 이동 제외
    > 해당 조건에 맞는 모든 곳을 찾는 것이므로 dfs를 사용하면 될 것 같다.

<br/>

- 인접한 몇 개의 국가가 몇 명의 인구를 이동시킬지 계산해야한다.
    > dfs의 파라미터로 좌표 값   
    인구 수와 국가의 개수를 누적시킨다.   
    연합 후의 인구 수 = 누적 인구 수 / 누적 국가의 개수

<br/>

- ~~이후 새로운 저장 배열(movingPeople)에 visited가 true인 좌표에 값이 있는지(0 초과인지) 확인 후 연합 후의 인구 수를 넣는다.~~
    > nations의 값을 바로 바꾸면 논리 오류가 발생할 가능성이 높기 때문이다.

<br/>

- 모든 칸의 검사가 끝났다면 +1일을 해준다.
    > movingDays++ / visited 초기화 / movingPeople의 값(0 초과)을 nations에 붙여넣기

<br/>

- 이후에 다시 국경을 열 수 있는지 확인하고 정답 출력
    > movingPeople의 값이 전부 0이면 국경을 열 수 없는 것이다.

<br/>

## 🐞 디버깅

- visited를 활용하면 국가 경계에 대해 잘못된 값이 덮어씌워질 수 있기 때문에 다른 방법을 찾아야한다.
    > List를 활용하여 연합이 된 국가들의 좌표를 넣어 안전하게 사람들의 평균을 ~~movingPeople에 넣어준다.~~    
    바로 nations에 넣어줘도 문제없다.

<br/>

- 검사한 visited를 다시 false로 복구하는 것 같이 visited를 건드리는 것은 대체로 올바른 방법이 아니었다.
    > 중복 탐색 등 다른 효율성이 떨어지는 문제가 있을 수 있기 때문에 최대한 visited는 확인 용도로만 쓰는 것이 좋은 것 같다.

<br/>

- 틀린 코드는 시간 효율이 O(n<sup>4</sup>)이어서 효율이 좋지 않았다.
    > 2차원 배열이 2개라 4중 for문이 되었었다.
