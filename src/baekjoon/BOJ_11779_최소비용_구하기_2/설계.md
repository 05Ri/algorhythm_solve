# ☑️ 문제
⛓️‍💥 [11779 최소비용 구하기 2](https://www.acmicpc.net/problem/11779)

## ⌨️ 입력

- 도시의 개수(1 ~ 1,000)
    > cityCnt

<br/>

- 버스의 개수(1 ~ 100,000)
    > busCnt

<br/>

- 버스의 정보 → 출발지의 도시 번호, 도착지의 도시 번호, 버스 비용
    > map[출발지][도착지] = 버스 비용

<br/>

- 출발지의 도시 번호, 도착지의 도시 번호
    > departure, arrival

<br/>

## 🖥️ 출력

- 출발지와 도착지의 최소 비용
    > minFee

<br/>

- 최소 비용을 갖는 경로에 포함되어있는 도시의 개수: 출발지, 도착지 포함
    > Queue의 길이

<br/>

- 최소 비용이 나오는 경로: 출발지와 도착지 포함
    > Queue로 구현해본다.

<br/>

## 💭 문제 조건 정의 & 해결

- 최소 비용을 구하는 문제이므로 다익스트라 알고리즘을 사용한다.
    > 최소 비용 뿐만 아닌, 어디를 거쳐가는지에 대한 경로도 구해야하므로 이를 저장할 큐를 생성해놓는다.

<br/>

## 🐞 디버깅

- 배열 선언 시 인덱스와 도시 번호가 일치하도록 하는 것이 중요
    > ArrayList 선언 시, cityCnt에 +1을 해주어야 원하는대로 동작함.   
    (0 ~ N - 1) X → (1 ~ N) O

<br/>

- for (요소 : 배열) {...} 방식은 단순 값만 꺼내오는 방식(값을 복사)으로, 초기화 방식에는 적합하지 않음
    > 인덱스로 직접 건드려주어도 되고, Arrays.fill(배열, 값)을 활용해본다.

<br/>

- 큐에 경로를 다 넣게 되면, 메모리 초과가 무조건 발생한다.
    > 경로를 담아 역추적 할 배열을 따로 생성한다.

<br/>

- **다익스트라의 핵심**
    > (다음 탐색할 도시의 최소비용) > (누적 비용) + (다음 도시로 들어갈 비용)   
    이라면 다음 탐색에 넣기

<br/>

- 조금 더 최적화
    > 우선순위 큐를 사용했으므로, 도착 도시가 나왔다는 것은 가장 빠른 경로라는 뜻이다. 따라서, 큐 poll을 하고 난 뒤의 현재 도시가 도착 도시와 같다면 바로 리턴시켜주는 것은 뒤에 있을 불필요한 계산을 전부 건너뛰는 것과 같다.
