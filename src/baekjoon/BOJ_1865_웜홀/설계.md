# ☑️ 문제
⛓️‍💥 [1865 웜홀](https://www.acmicpc.net/problem/1865)

## ⌨️ 입력

- 첫 번째 줄은 테스트 케이스 개수
    > testCase

<br/>

- 각 테스트 케이스의 첫 번째 줄은 [지점의 수, 도로의 개수, 웜홀의 개수]가 차례대로
    > 지점: 1 ~ 500   
    도로: 1 ~ 2,500   
    웜홀: 1 ~ 200

<br/>

- 각 테스트 케이스의 두 번째 줄부터는 도로의 개수만큼, 웜홀의 개수만큼 정보가 주어진다.
    > 도로 정보: [연결된 지점1, 연결된 지점2, 이동 시간]   
    웜홀 정보: [시작지점 , 도착 지점, 줄어드는 시간]   
    시간: 0 ~ 10,000

<br/>

## 🖥️ 출력

- 시간이 줄어들면서 돌아오는 것이 가능한지 여부
    > "YES" 또는 "NO"

<br/>

## 💭 문제 조건 정의 & 해결

- 간선 중에 음수가 있기 때문에 다익스트라를 쓰면 안된다.
    > 그렇다고 모든 경우의 수를 따지기에는 시간이 너무 오래걸릴것이다. 다른 방법을 찾아야한다.

<br/>

- 다익스트라를 이용하여 시작 위치에서 탐색을 시작하여 다시 시작 위치가 나왔을 때, 시간이 음수면은 성공?
    > 다만, 돌아가는 웜홀이나 도로가 없을 경우에는 최악의 경우(모든 길을 전부 찾는)가 되므로 이 방법은 아닐 것이다.

<br/>

- ~~웜홀을 이용하자...!!~~
    > ~~웜홀의 시간보다 다익스트라를 이용하여 도로를 탐색한 가장 짧은 시간이 더 작은 경우가 하나라도 있다면, "YES" 이다. 따라서 다익스트라를 사용하는 횟수가 원래 생각했던 것보다 획기적으로 줄어들 것이다. 웜홀은 단방향이기 때문에 시작지점과 끝지점이 명확하다.~~

<br/>

- ~~도로는 양방향이고, 중복된 경로가 있을 수 있음.~~
    > ~~중복된 경로 중 가장 짧은 경로를 해줘야 다익스트라를 돌릴 때 가지 수가 많이 줄어든다. 리스트로 관리하면 정렬 및 비교를 해주는 작업이 필요하므로, 각 경로는 인접리스트로 관리하는 것이 편리할 것 같다.~~

<br/>

## 🐞 디버깅

- 다익스트라 자체를 사용하면 안됨.
    > 음수 간선이 존재하기 때문에 완전히 오작동한다. **벨만-포드 알고리즘**을 사용해야한다.   
    또한, 웜홀의 개수가 많으면 많을수록 돌려야하는 다익스트라가 많아지기 때문에 시간초과가 날 수 있다.

<br/>

- 벨만-포드 알고리즘
    > (전체 노드의 개수 - 1)번만큼 전체 노드를 돌면서 최소 비용을 계산해준다. 간선의 수가 (N - 1)이기 때문이다! 이후 모든 노드를 돌면서 최소 비용이 갱신이 된다면 **음의 사이클**이 존재한다는 것이기 때문에 답을 낼 수 있다.

<br/>
