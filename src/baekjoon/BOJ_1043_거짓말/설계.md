# ☑️ 문제
⛓️‍💥 [1043 거짓말](https://www.acmicpc.net/problem/1043)

## ⌨️ 입력

- 첫째 줄: 사람의 수 N / 파티의 수 M
    > N, M → 1 ~ 50

<br/>

- 둘째 줄: 진실을 아는 사람의 수 T / 사람들의 번호
    > T → 0 ~ 50

<br/>

- 셋째 줄~: 각 파티마다 오는 사람의 수 P / 사람들의 번호
    > P → 1 ~ 50

<br/>

## 🖥️ 출력

- 지민이가 과장되게 말해도 되는 파티의 개수
    > 

<br/>

## 💭 문제 조건 정의 & 해결

- 진실을 아는 사람이 없을 때에는 모든 파티에서 과장되게 말해도되므로 파티의 개수가 정답이 된다.
    > 

<br/>

- 진실을 아는 사람이 있다면, 그 사람 및 같이 있던 사람들까지 어느 파티에 있어야하는지 알아야한다.
    > 즉, 진실을 아는 사람들과의 관계를 알아내고, 소외된 파티가 있는지 확인한다.

<br/>

- 각 사람들끼리 어느 파티에서 만났는지 리스트(그래프)를 작성한다.
    > 서로 영향을 줄 수 있으므로 양방향으로 한다.

<br/>

- 소외된 파티를 확인하기 위해 파티도 저장해놓는다.
    > parties[N][]

<br/>

- 진실을 아는 사람을 확인하는 booelan 배열을 생성하여 그래프를 순회한다.
    > 확인하여 참이면 true

<br/>

- 모든 진실을 아는 사람들의 시작점을 확인했다면, 해당 사람들이 없는 파티가 있는지 확인한다.
    > 진실을 아는 사람 및 같이 있던 사람들을 제외한 파티가 있는 개수가 정답

<br/>

- 우려사항
    > 위 같이 여러 배열을 활용하면 수가 적다고 해도 128MB를 초과할 것 같다는 예감이 든다.

<br/>

## 🐞 디버깅

- Union-Find라는 알고리즘의 개념을 알게 되었다.
    > 단순 set이나 배열로 이런 집합적인 문제를 구현하게되면 관리해야할 것들과 구현이 굉장히 복잡해진다.   
    따라서 이런 **연결 관계** 문제에서 많이 쓰이는 알고리즘이다.

<br/>

- 코드 구조
    ```java
    static int[] parent;

    static int find(int x) {
        if (parent[x] == x) return x;
        // 경로 압축
        return parent[x] = find(parent[x]);
    }

    static void union(int a, int b) {
        int pa = find(a);
        int pb = find(b);
        if (pa != pb) {
            // 한쪽을 다른 쪽 부모로 붙임
            parent[pb] = pa;
        }
    }
    ```
